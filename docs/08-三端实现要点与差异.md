## 3. 密码自动填充实现要点

### 3.1 Android（AutofillService）

```
1. 实现 AutofillService（Kotlin），在 AndroidManifest 注册
2. onFillRequest 中解析 AssistStructure：
   - 遍历 ViewNode，识别 username / password / otp 字段
   - 依据：inputType、hint、idEntry、webDomain
3. 构造 Dataset：
   - 每个匹配条目一个 Dataset
   - 用 Dataset.Builder + setValue(id, AutofillValue.forText(...), presentation)
4. onSaveRequest：捕获用户提交的新凭据，回调 Flutter 侧保存
5. 需处理：
   - 包名 → 条目匹配（存 meta.android_package）
   - WebView 内的表单（webDomain）
   - 多步骤登录（先用户名后密码）
```

**难点**：字段识别准确率。建议内置一份常见 App 的包名映射表（可选，不强制）。

### 3.2 iOS（AutoFill Credential Provider）

```
1. 新建 Credential Provider Extension target（Swift）
2. 实现 ASCredentialProviderViewController
3. 主 App 通过 App Group 共享数据（共享一个 Keychain Access Group）
4. 流程：
   - Extension 被系统唤起 → 读取共享区中的条目列表（只需域名/用户名/标题，不含密码）
   - 用户选中某条 → Extension 请求主 App 解锁 → 主 App 通过共享 Keychain 写入一次性 token
   - Extension 用 token 取密码 → completeRequest(withSelectedCredential:)
5. 限制：Extension 内存上限约 120MB，不能加载大模型
```

**注意**：iOS 要求 Extension 独立签名、独立 entitlements，且**审核会重点检查**
「是否在 Extension 内明文存储密码」。必须做到：密码只在主 App 解密，Extension 通过一次性 token 获取。

### 3.3 Windows（无系统填充）

Windows 没有面向第三方的系统级密码填充 API。方案：

| 方案 | 体验 | 建议 |
|---|---|---|
| 手动复制 + 剪贴板 30 秒后自动清除 | 一般 | ✅ 一期 |
| 全局热键呼出快速搜索 → 回车复制 | 较好 | ✅ 一期 |
| 浏览器扩展 | 好 | ❌ 用户明确不做 |
| 模拟键盘输入 | 差且不安全 | ❌ 不做 |

**产品策略**：Windows 端密码模块定位为「查看 + 复制 + 生成 + TOTP」，
不承诺自动填充。设置页明确说明，避免用户预期落空。

## 4. 剪藏入口

### 4.1 Android

```xml
<!-- AndroidManifest.xml -->
<intent-filter>
  <action android:name="android.intent.action.SEND" />
  <category android:name="android.intent.category.DEFAULT" />
  <data android:mimeType="text/plain" />
</intent-filter>
```

- 用 `receive_sharing_intent` 接收
- 需处理：App 未运行时冷启动接收、多 URL 分享、纯文本无 URL

### 4.2 iOS Share Extension

```
1. 新建 Share Extension target（Swift）
2. 在 Info.plist 声明 NSExtensionActivationRule（URL + Text）
3. 从 extensionContext.inputItems 取 URL
4. 通过 App Group + UserDefaults(suiteName:) 或共享文件写入待处理队列
5. 唤起主 App（用 custom URL scheme），主 App 启动时消费队列
```

**限制**：Extension 不能长时间运行（约 30s），所以**只做「接收 URL」，不做抓取**。
抓取交给主 App。

### 4.3 Windows

- `hotkey_manager` 注册全局热键（默认 `Ctrl+Shift+V`）
- 托盘常驻（`tray_manager`）
- 监听剪贴板（`clipboard_watcher`），检测到 URL 时托盘气泡提示

## 5. 后台任务

| 平台 | 机制 | 现实约束 | 产品文案 |
|---|---|---|---|
| Windows | 托盘常驻 + 定时器 | 无 | 「自动同步与归档」 |
| Android | `workmanager` | Doze 模式会延后 | 「App 运行时同步」 |
| iOS | BGTaskScheduler | 每天可能只给几分钟 | 「打开 App 即同步」 |

**统一策略**：前台补偿。App 启动 / 回到前台时检查积压任务并执行。
这是唯一可靠的方式，不要指望后台。

## 6. 生物识别解锁

```
启动流程：
  1. 检查是否已设置生物识别解锁
  2. 是 → 直接调系统生物识别
       ├ 成功 → 从安全存储取 DEK（被生物识别保护的条目）→ 进主界面
       └ 失败 → 退回主密码输入
  3. 否 → 主密码输入
```

**安全要求**：
- 生物识别保护的 DEK 必须用 `flutter_secure_storage` 的 `biometricOnly` 选项存储
- 生物识别失败 5 次 → 强制主密码
- 主密码连续错误 10 次 → 锁定 5 分钟（本地，防暴力）

| 项 | Android | iOS | Windows |
|---|---|---|---|
| 导航 | Material 3 + 底部导航 | Cupertino 风格 + 底部 Tab | 侧边栏 + 三栏布局 |
| 列表操作 | 长按菜单 | 侧滑操作 | 右键菜单 |

| 窗口 | — | — | 可调整大小，最小 900×600 |

## 8. 打包与分发

| 平台 | 包体目标 | 注意 |
|---|---|---|
| Android | APK < 60MB / AAB | 内置 25MB 模型；大模型按需下载 |
| iOS | IPA < 80MB | App Store 蜂窝下载限制 200MB |
| Windows | MSIX < 70MB | 需检测 WebView2 运行时，缺失时引导安装 |

**Windows 特有**：WebView2 Runtime 不是所有机器都有（Win10 早期版本）。
必须在启动时检测，缺失时提示下载（或打包 fixed-version runtime，体积 +150MB）。

## 9. 三端一致性要求

必须保持一致（不允许平台差异）：

- 数据模型、同步协议、加密格式
- `canonicalizeJson` 实现（否则跨端 hash 校验失败）
- HLC 生成规则
- 冲突规则矩阵
- 工具集与隐私分级

允许有差异：

- UI 布局与交互习惯
- 后台任务可靠性
- 密码填充能力（Windows 无）
- 本地模型尺寸上限

## 10. 各端专项验收

| 平台 | 专项验收 |
|---|---|
| Android | 分享入口冷启动可用；Autofill 在 5 个常见 App 上能正确识别字段 |
| iOS | Share Extension 30s 内完成接收；Credential Provider 审核通过 |
| Windows | WebView2 缺失时有明确引导；全局热键不与其他软件冲突；托盘常驻 24h 稳定 |
| 三端 | 同一 vault 在 3 台设备上同步 1000 条，最终一致 |
