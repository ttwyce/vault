## 9. 工程规范

- **目录结构**（feature-first）
```
lib/
  app/            应用壳、路由、主题、启动流程
  core/           crypto, hlc, log, result, extensions
  data/
    db/           drift schema, migrations, dao
    webdav/       backend, capability, xml
    sync/         engine, state_machine, merger, conflict
    model_hub/    manifest, downloader, registry
    search/       fts, vector, fusion
  domain/         entities, usecases, services
  features/
    entries/      列表 / 编辑器 / 详情
    archive/      剪藏 / 阅读器 / 快照
    vault/        密码面板 / TOTP / 健康报告
    agent/        对话 / 工具 / 隐私闸门
    settings/     同步 / 模型 / 隐私 / 关于
  platform/       原生通道封装（autofill, share, pdf）
```

- **错误处理**：统一 `Result<T, AppError>`，禁止在 UI 层 catch 裸 Exception
- **日志**：分级 + **自动脱敏**（任何 entry 正文、密码、token 不得进日志）
- **迁移**：drift schema 版本化，每次迁移必须有测试
- **依赖锁**：`pubspec.lock` 必须提交；`flutter_edge_ai` 这类高频迭代包固定精确版本

## 11. 依赖现状更新（2026-11-08 实测）

初始化工程时按本文档装依赖，发现两处与文档不符，已就地修正。

### 11.1 SQLite 原生库：`*_flutter_libs` 全部 EOL

| 包 | 实测结果 |
|---|---|
| `sqlcipher_flutter_libs` | 解析到 `0.7.0+eol`（已停止维护） |
| `sqlite3_flutter_libs` | 解析到 `0.6.0+eol`（已停止维护） |

**原因**：`sqlite3` 3.9 起改用 **Dart Native Assets**（`hook/build.dart` + `code_assets`），
原生库由包自己构建/下载，不再需要额外的 `*_flutter_libs` 转发包。

**处理**：两个包都已移除，只保留 `sqlite3`（drift 的传递依赖）。

### 11.2 数据库加密：已定为 A 方案，并实测通过

`sqlcipher_flutter_libs` 已 EOL，但**结论不是「要自建构建」，而是「一行配置」**。

`sqlite3` 3.9 的 native-assets 构建钩子（`lib/src/hook/compile/description.dart`）
**原生支持把预编译产物换成 SQLCipher**：

```yaml
hooks:
  user_defines:
    sqlite3:
      source: sqlcipher     # 可选 sqlite3（默认）/ sqlite3mc / sqlcipher
```

预编译产物覆盖我们需要的全部组合：

| 平台 | 可用 ABI |
|---|---|
| Android | arm / arm64 / ia32 / x64 |
| iOS | arm64（device）/ arm64 + x64（simulator） |
| Windows | x64 / ia32 / arm64 |

**所以：不需要自建构建脚本、不需要 CI 矩阵、不需要 vendored 二进制。**

实测结果（`test/sqlcipher_probe_test.dart`，Windows x64 宿主）：

| 验证项 | 结果 |
|---|---|
| `PRAGMA cipher_version` | `4.20.0 community` ✅ |
| 错误密钥打开加密库 | HMAC 校验失败，抛错 ✅ |
| FTS5 建表 + 中文 + 英文查询 | ✅（中文需应用层切分，见 06 §1.3） |
| WAL + 200 行写入 | ✅ |

三个方案对比（结论：A）：

| 方案 | 做法 | 判断 |
|---|---|---|
| **A. SQLCipher 整库加密** | `source: sqlcipher` 一行配置 | ✅ **采用**。成本约 1 人日 |
| B. 应用层字段加密 + 明文索引 | 正文 AEAD 落库，FTS 索引单独明文 | ❌ 索引里是全文，拖库即还原全部内容 |
| C. 依赖系统盘加密 | 不做库加密 | ❌ 与「设备丢失防护」承诺不符 |

**为什么 B 不能作为最终方案**：`entry_fts` 存的是正文的 token 流，
`entry_history` / `trash` / `activity` 也都含明文。任何能拿到 db 文件的人
（iCloud 备份、越狱、取证镜像、备份排除规则写错）都能还原全部笔记与密码。

**但 B 不是白做的**：字段级 AEAD 是**同步层**的必需品（上传到 WebDAV 的每条 item
都要独立加密），和「本地库是否整库加密」是两个层，两件都要做。

> 唯一需要注意：`package:sqlite3` 发布的 SQLCipher 构建，其 SQLite 版本
> 可能比默认构建**略旧**（官方文档明示）。FTS5 语法多年稳定，风险低；
> 若将来要用新版本才有的特性，需回看这一点。

### 11.3 本机工具链限制（非代码问题）

| 命令 | 现象 | 结论 |
|---|---|---|
| `flutter devices` | 被安全策略拦在 `reg.exe`（查 Edge 版本） | 已知项，不影响构建 |
| `flutter test` | `flutter_tester` 连不上 `127.0.0.1` | **不是沙箱限制**：本机有 `http_proxy=127.0.0.1:51096`，本地 WebSocket 被代理拦截。设 `NO_PROXY=127.0.0.1,localhost,::1` 即可，43 条测试全绿 |
| `flutter analyze` | 正常 | 日常验证手段 |

验收仍以 `flutter build apk --release` 为准（见 `C:\Android\AGENTS.md` §7）。

| 导入上限 | 40 MB / 文件 | 超过基本是多字重 ttc，加载会 OOM |
| 运行时注册 | `FontLoader`（`package:flutter/services.dart`） | **只能加、不能卸**；家族名用内容哈希去重 |
| 持久化 | `<appSupport>/fonts/index.json` + `files/<sha256>.ttf` | 不进数据库，必须在 DB 打开前可读 |
| 同步 | **不同步** | 纯本机偏好，见 15 §6 |
| 文件选择 | `file_picker` 13.3.2 | `FilePicker.pickFiles()` 直接返回 `List<PlatformFile>`（13.x 无 `allowMultiple` 参数、无 `.platform` getter） |

**13.x 的 `file_picker` 与常见教程里的 8.x 写法完全不同**，两个坑：

```dart
// 8.x（已不适用）
final result = await FilePicker.platform.pickFiles(allowMultiple: true);
if (result != null) { result.files ... }

// 13.x（现行）
final List<PlatformFile> picked = await FilePicker.pickFiles();
for (final f in picked) { f.name; await f.readAsBytes(); }
```

`PlatformFile.path` 在 Android 的 `content://` 下为 null，**必须走 `readAsBytes()`**。

## 13. 加密依赖定案（2026-11-08）

### 13.1 不引入 `sodium_libs`

原计划用 `sodium_libs` 做 XChaCha20-Poly1305。实现时改成**全部走 `cryptography`**：

| 需求 | `cryptography` 提供 | 是否够 |
|---|---|---|
| XChaCha20-Poly1305 | `Xchacha20.poly1305Aead()` | ✅ 24B nonce、支持 AAD |
| Argon2id | `Argon2id(...)` | ✅ 纯 Dart + isolate 并行 |
| HKDF-SHA256 | `Hkdf(hmac: Hmac.sha256())` | ✅ |
| 常量时间比较 | 自己写 8 行 | ✅ |

**理由**：一个包覆盖全部需求，少一套原生依赖就少三端各一次的构建/兼容验证。
`sodium_libs` 的唯一优势是 C 实现更快，而我们的热点只有 Argon2（它本来就在
`cryptography` 里）—— XChaCha 加密的对象是几十到几百字节的字段，纯 Dart 足够。

### 13.2 `crypto` 与 `cryptography` 并存

两个包名字像但职责不重叠，不要试图统一：

- `crypto`（Dart 官方）：`sha256`、`hmac` —— 用于 `content_hash`、指纹、BIP-39 校验和
- `cryptography`：AEAD、KDF —— 用于包裹与派生

### 13.3 Argon2id 是纯 Dart，必须实测

`cryptography` 的 Argon2id 是纯 Dart 实现（会起 isolate，但每 lane 仍是 Dart）。
实测桌面 JIT：`m=64MB t=3 p=4` → **2147 ms**，是设计阶段推测值的两倍以上。

保留 64MB 的理由是行业基线（与 Bitwarden 默认值一致），
但**解锁页必须有进度反馈且派生不阻塞首帧**。完整数据与决策见
[16 密钥与恢复码](16-密钥与恢复码.md) §3。

`test/kdf_perf_probe_test.dart` 会持续测量这组数字 —— 它是测量，不是断言。
