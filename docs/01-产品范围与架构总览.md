# 01 · 产品范围与架构总览

## 1. 目标用户与核心场景

**目标用户**：有信息囤积习惯、在意数据主权、愿意配置一次 WebDAV 的个人用户（开发者、研究者、内容工作者）。

**三个必须打透的场景**：

| 场景 | 现状痛点 | 本产品的解法 |
|---|---|---|
| S1 找回 | 三个月前看过一篇文章，只记得大概讲什么，浏览器历史里翻不到 | 网页归档 + 混合检索 + AI 直接给出可点击入口 |
| S2 随手记 | 想法一闪而过，打开笔记 App 的 3 步成本劝退 | 全局热键 / 悬浮球 / 分享菜单，1 步进入输入 |
| S3 沉淀 | 日记写了不回顾，等于没写 | AI 每日时间线 + 周/月滚动摘要 + 可溯源 |

## 2. 功能边界

### 做

- 统一条目库（笔记 / 想法 / 日记 / 网页书签 / 密码）
- 端到端加密 + WebDAV 多端同步（含冲突副本）
- 网页正文提取 + PDF 快照 + 死链与变更检测
- 全文检索 + 语义检索 + 混合排序
- 端侧 AI：日总结、AI 日记、带引用的问答
- 密码条目管理（TOTP、健康报告、原生自动填充）
- 端侧向量模型一键下载与管理

### 明确不做（第一期）

| 不做 | 原因 |
|---|---|
| Web 端 | SQLCipher / sqlite-vec / 大模型在浏览器端不可用或不成熟 |
| 自建后端 / 账号体系 | 架构前提是零服务端 |
| 多用户共享 / 协作 | 无后端无法做权限与实时同步 |
| MCP 接入 | 本期先留接口（`AgentTool` 抽象），二期实现 |
| 脚本型 Skill | 移动端无 shell，仅 Windows 可行，二期 |
| 服务端网页抓取 | 与零知识加密冲突，全部在客户端完成 |
| 浏览器扩展 | 用户明确不做，Windows 端密码填充降级为手动复制 |

```
└─────────────────────────────────────────────────────────────┘

┌─────────────────────────────────────────────────────────────┐
│                      Domain Layer (UseCases)                 │
│  EntryService  ArchiveService  SearchService  AgentRuntime   │
└─────────────────────────────────────────────────────────────┘
        │              │              │              │
┌───────────┐  ┌───────────┐  ┌───────────┐  ┌───────────┐
│  Storage  │  │   Sync    │  │ Retrieval │  │   Agent   │
│ (drift +  │  │ (WebDAV + │  │ (FTS5 +   │  │ (LLM +    │
│ SQLCipher)│  │  Merger)  │  │  Vector)  │  │  Tools)   │
└───────────┘  └───────────┘  └───────────┘  └───────────┘

┌─────────────────────────────────────────────────────────────┐

└─────────────────────────────────────────────────────────────┘
```

### 3.1 Storage
- SQLCipher 加密的 SQLite（drift），唯一事实来源
- 所有写操作经 `WriteGateway`，保证「先写 oplog 再改实体」

### 3.2 Sync
- WebDAV 客户端 + 能力探测
- 三级变更探测、状态机、三方合并、墓碑、回收站

### 3.3 Retrieval
- FTS5（BM25）+ sqlite-vec（KNN）+ 结构化过滤 → RRF 融合
- embedding 模型管理（下载、校验、索引重建）

### 3.4 Agent
- OpenAI 兼容云模型（BYOK）+ 端侧模型（flutter_edge_ai）
- 工具注册表 + 风险分级 + 隐私闸门
- 日总结流水线、滚动摘要

## 4. 关键数据流

### 4.1 写入

```
用户编辑
  → WriteGateway.write(entry)
      → BEGIN TRANSACTION
        → append oplog(op=update, payload=encrypt(entry))
        → UPDATE entry SET ..., rev=rev+1, hlc=now_hlc()
        → UPDATE entry_fts
        → mark vec stale
      → COMMIT
  → SyncScheduler.kick(debounce 8s)
  → EmbeddingQueue.enqueue(entry.id)
```

**关键**：本地写入永不等待网络。同步和向量化都是异步后台。

### 4.2 同步

```
SyncScheduler
  → L1 探测（devices/ 水位，1 请求）
     └ 无变化 → 结束
  → L2 发现（sync-collection 或 16 分片 PROPFIND）
  → 拉墓碑 → 拉 meta → 拉条目（按需）
  → 合并（三方 / LWW / 冲突副本）
  → 推送 oplog 中 applied=0 的操作（If-Match）
  → 校验（content_hash 对账）
```

### 4.3 检索

```
查询
  → 并行：FTS5 top50 + 向量 KNN top50
  → 结构化过滤（kind / 时间 / 标签 / 归档状态）
  → RRF 融合（k=60）
  → 返回 entry 摘要卡片
```

### 4.4 AI 问答

```
用户提问
  → Intent 分类（检索 / 生成 / 操作）
  → 工具循环（search_entries → get_entry → 生成）
  → 输出：答案 + citations（可点击 entry 卡片）
```

## 5. 设计原则（评审时的判据）

| 原则 | 含义 | 反例 |
|---|---|---|
| **Local-first** | 本地是唯一事实来源，网络是增强 | 列表页等网络返回才渲染 |
| **降级可用** | 任一子系统失效，其余功能仍可用 | 模型没下载 → 搜索不可用（错） |
| **永不覆盖** | 任何自动流程不得静默覆盖用户内容 | 同步时直接 PUT 远端版本 |
| **隐私分级** | 数据按敏感度决定能否出设备 | 把密码明文塞进 prompt |
| **可溯源** | AI 的每条结论必须能点回原文 | AI 日记没有引用 |
| **可中断** | 长任务必须支持暂停/续跑 | 全量重建向量不可中断 |

## 6. 名词表

| 术语 | 含义 |
|---|---|
| **entry** | 统一条目，`kind` 区分笔记/想法/日记/书签/密码 |
| **vault** | 一个加密库，对应一个 WebDAV 目录 |
| **HLC** | 混合逻辑时钟，`ms:counter:deviceId`，用于跨设备排序 |
| **base** | 上次同步成功时的条目版本，三方合并的基准 |
| **tombstone** | 删除墓碑，防止「删除」与「编辑」冲突时丢数据 |
| **blob** | 内容寻址的二进制块（网页快照、附件） |
| **L0/L1/L2** | 隐私分级：端侧 / 脱敏云端 / 全量云端 |
| **RRF** | Reciprocal Rank Fusion，多路检索结果融合算法 |
| **MRL** | Matryoshka Representation Learning，向量可裁剪降维 |
