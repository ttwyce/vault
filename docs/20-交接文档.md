### 3.1 #13：真实加密载荷边界（已完成，已验证）

新增 / 修改：

- `lib/core/sync/encrypted_sync_codec.dart`
  - `EncryptedSyncPayloadCodec implements AsyncSyncPayloadCodec, SyncEntityPayloadCodec`
  - `K_name` HMAC 生成 `[0-9a-f]{32}.enc` 云端文件名，entry / category / tag / `entry_taxonomy` 域分离
  - `K_item` 封 `EntrySnapshot` / `SyncTombstone` / `TaxonomySnapshot`
  - `K_meta` 封 `/vault/meta.enc` 的 `SyncVaultMeta(vault_id, schema)`
  - 设备水位 `/vault/devices/*.json` 按 docs/04 §2 保持明文，ETag 只来自响应头
  - 解码时交叉校验信封明文头、实体、id、rev 与 `content_hash`
- `lib/core/sync/sync_payloads.dart`
  - 新增 `AsyncSyncPayloadCodec`、`SyncPayloadCodecAdapter`
  - 新增 `SyncEntityPayloadCodec`、`SyncEnvelopeHeader`
  - `SyncPendingOp.upsert` 支持 `rawPayload`：oplog 信封字节可原样 PUT，不重新加密
  - `SyncEntity` 新增 `sync_meta` / `tombstone`
- `lib/core/sync/sync_engine.dart`
  - 改为依赖异步 codec；所有 `encode*` / `decode*` / `hashedName` 均 `await`
  - `SyncRunResult` 新增 `quarantinePayloads`、`nextHlc`、`cloudAppliedEntryIds`
  - 坏文件隔离时保存原始字节，供数据库侧写入 `sync_quarantine`
  - `cloudAppliedEntryIds` 只允许云端已确认的快照在 DB 落库时标记 oplog `applied=1`
- `test/encrypted_sync_codec_test.dart`
  - 7 条测试：HMAC 文件名、AAD / 头部篡改、错误密钥、meta 子密钥隔离、墓碑实体、taxonomy 实体、明文水位
- `test/sync_engine_test.dart`
  - 内存 JSON codec 改用 `SyncPayloadCodecAdapter`，21 条编排测试保持通过

#13 定向验证：`flutter analyze` 无告警；`flutter test test/encrypted_sync_codec_test.dart test/sync_engine_test.dart` 为 `+28: All tests passed!`。

### 3.2 #14：数据库工作区与事务落库（代码已落地，专用测试未完成）

新增 / 修改：

- `lib/core/sync/cloud_layout.dart`
  - 新增 `/vault/entities/<shard>/` 独立命名空间及 `entitiesDir()` / `entityItemPath()`
  - 目的：category / tag / `entry_taxonomy` 不能再放进 `/vault/items/`，否则正文同步器会把 taxonomy 信封误当成 `EntrySnapshot`
- `lib/data/write/write_gateway.dart`
  - `applySyncRun(SyncRunResult)`：在一个 drift 事务里落实体、历史、回收站、FTS、oplog、`sync_state`、`device_watermark`、`sync_log` 与隔离区；先校验全部 `content_hash`，任一失败整体回滚
  - `recordEntityPushes(...)` / `applyRemoteTaxonomySnapshots(...)`：taxonomy 独立通道的落库入口（通道编排本身尚未实现）
  - `quarantine()` 与 `_ensureQuarantineTable()`：用原生 SQL 建 `sync_quarantine`，不做 drift codegen / `schemaVersion` 升级
  - `_commit(...)` / `_commitTaxonomy(...)` 增加 `applied` 参数，允许「云端已确认」的远端快照直接写 `applied=1`
  - `_replaceSyncState(...)` / `_upsertSyncState(...)` / `_markAppliedOps(...)` / `_persistPublishedWatermark(...)` / `_writeSyncLogRecord(...)`
  - `_validateEntrySnapshot(...)` 会重算 `content_hash`，防止坏合并结果落库
- `lib/data/sync/sync_workspace_store.dart`
  - `DbSyncWorkspaceStore.load()`：从 `sync_state` / `device_watermark` / `entries` / 已应用 oplog / 待推 oplog 装配 `SyncWorkspace`
  - 复用 `EncryptedSyncPayloadCodec.hashedName()` 得到 HMAC 文件名
  - `pendingOps` 的 `rawPayload` 直接取 oplog 信封字节
  - `commit()` / `run()`：`load → SyncEngine.run → gateway.applySyncRun`
- `lib/data/db/tables/log_tables.dart`
  - `SyncEntity.syncMeta`、`SyncEntity.tombstone` 常量

**注意**：#14 的 `DbSyncWorkspaceStore` 与 `applySyncRun()` 目前只有 `flutter analyze` 与全量测试间接覆盖，**还没有专用数据库集成测试**。交接后第一件事就是补：

4. 断言 `sync_quarantine` 保存了损坏载荷原始字节
