## 0. 最高优先级：禁止重复工作

用户已明确指出开发长期在做同质化重复。以下规则**优先于**「继续推进」类目标：

1. **不得再为凑轮次新增横向小模块**。过去几十轮的模式是「从 docs 挑一个缺口 → 写纯判定层 + 专用测试 → 刷 CHANGELOG/README 数字 → 全量验证 → 推送 → 贴同模板收尾报告」。这种模式已产生 D1~D110、v1.5x~v2.5 与 990→1069 的测试数增长，但**不是阶段性跃迁**，现予终止。
2. **新增任何代码前必须满足三选一**，否则不做：
   - (A) **装配层接线**：把已写好的客户端/服务注入 App 启动与页面（见 §5 清单）；
   - (B) **跨链路集成**：把两条以上已落地链路串成一条真实端到端路径并测试；
   - (C) **真实外部条件验证**：WebDAV 账号、真机、原生能力、云 Key 等到位后的验收。
3. **明确禁止的重复动作**：
   - 再写「纯判定层 / 状态机变体 / 徽章映射 / 审计规则 / meta 模型 / 排期判定」小模块；
   - 对同一能力再包一层 `http_*` 客户端；
   - 复制粘贴同结构测试来增加计数；
   - 每版重复编辑 README / 09 / 14 / 20 的同一句数字说明；
   - 改写历史提交、重推、重复署名修复；
   - 对同一后台任务反复 `sleep` + 同一参数 `job_output` 轮询（改用一次等待或前台超时）；
   - 每轮粘贴「规模 / 边界 / 剩余项」同模板收尾报告。
4. **收口判定**：连续两轮找不到满足三选一的新工作时，输出「可实现项已穷尽」的收口说明并停止新增批次，**不制造工作**。
5. **文档维护**：只在结构性变更时记 CHANGELOG；当前测试数字只放 README 一处；历史日志数值保持原样，不回填。
