## 1. 为什么字体要单独做一个子系统

这个产品的视觉身份**几乎全部由字体承担**。

手绘风的三根支柱里，不规则圆角、虚线描边、硬阴影都是"形状"，用户看三秒就习惯了；真正决定"这是一本手写笔记本还是又一个 SaaS"的，是**字是不是像手写的**。而这件事在 Android 上是没有默认答案的 —— 系统只有黑体和宋体。

于是引出三个必须一起解决的问题：

| 问题 | 如果不解决 |
|---|---|
| 三端字体不一致 | Windows 上像手写笔记，Android 上像记账 App，同一个产品两个观感 |
| 用户想换成自己买的字体 | 只能等开发者发版，且开发者的审美不一定对 |
| 换字体后排版崩掉 | 行高、字号、等宽对齐全部要重调，改一处崩一片 |

所以字体不是"一个设置项"，是**一套和色板平级的令牌系统**：有角色、有回退链、有持久化、有加载生命周期。

## 2. 三个角色，而不是一个全局字体

代码里 `FontRole` 只有三个值：

| 角色 | 用在哪 | 为什么单独分出来 |
|---|---|---|
| `ui` | 列表、按钮、笔记正文、输入框 | 用量最大，决定整体气质。换它等于换皮肤 |
| `display` | 页面标题、品牌字标、卡片大标题 | 可以比正文更夸张；用纯手写西文（Caveat）时不希望正文也变成那个样子 |
| `mono` | 时间戳、字数、标签、TOTP 秒数、代码块 | **等宽体唯一不可替代的价值是数字列自动对齐**，这一点和"好不好看"无关 |

分成三个而不是"一个全局 + 几个例外"，原因是手绘风的核心是**两套声音**：书写体讲内容，等宽体报数据。一套字体同时干这两件事，层级立刻塌掉。

> 反例：如果只有一个全局字体，`14:02`、`4,182 字`、`#webdav` 会和正文完全同质，用户扫视时找不到"锚点"。而所有做得好的编辑类产品（iA Writer、Bear、Obsidian 的默认主题）都在元数据上用了第二套字体。

## 3. 内置三套字体

全部 SIL OFL 1.1，可商用、可随包分发、只需保留声明（见 `assets/licenses/font-notices.txt`）。

| 字体 | 家族名 | 文件 | 体积 | 覆盖 | 角色 |
|---|---|---|---|---|---|
| **霞鹜文楷 Lite** | `SketchWenKai` | `LXGWWenKaiLite-Regular.ttf` | 13.3 MB | 中 / 西 / 符号 | ui + display |
| **Caveat** | `SketchCaveat` | `Caveat-Variable.ttf` | 394 KB | 仅拉丁 | display |
| **JetBrains Mono** | `SketchJetBrainsMono` | `JetBrainsMono-Regular.ttf` | 264 KB | 拉丁 / 符号 | mono |

### 3.1 为什么内置而不是下载

模型（EmbeddingGemma 330MB）走"一键下载"是对的，字体不能这么干：

- 字体是**首帧**的一部分。先渲染系统字体再切成手写体，用户会看到一次明显的跳变，比一直用系统字体更糟。
- 内置总共 13.9 MB，对 200MB 的 AAB 上限毫无压力；下载方案反而要处理"用户没下载时界面长什么样"这个问题 —— 答案是"很难看"。

### 3.2 为什么中文只有一套

任何一个覆盖 GB2312 的中文字体都在 10 MB 量级。放三套就是 40 MB，换来的差异只有"楷体 / 宋体 / 黑体"这一点点 —— 而黑体和宋体系统里本来就有。

所以策略是：**中文内置一套（文楷），其余走导入或系统字体**。

### 3.3 为什么没有多字重

`LXGW WenKai Lite` 只有 Regular。粗体由引擎合成（Skia faux-bold），在手写体上观感可接受 —— 因为手写体本身的笔画粗细就不均匀，合成加粗的失真反而不明显。

**这是有意的取舍**：真要多字重就得换成完整版文楷（20MB+）并逐个声明 `weight`，包体和加载时间都不划算。如果以后有用户抱怨粗体糊，再补一版 `Medium` 即可（pubspec 加一行，代码零改动）。

### 3.4 回退链是硬要求

```dart
// FontCatalog.cjkFallback
'LXGW WenKai' → 'Kaiti SC' → 'STKaiti' → 'KaiTi' → 'PingFang SC'
  → 'Microsoft YaHei' → 'Noto Sans CJK SC' → 'sans-serif'
```

**不存在一个字体同时覆盖中文、西文和全部符号。** 少一个回退项，用户就会在某个页面看到"方框"。所以每个 `FontFace` 都必须带非空 `fallback`，这是 `FontStack` 的不变量。

## 4. 四套预设

用户不需要理解"角色"，点一个名字就得到完整的一套观感。

| 预设 | ui | display | mono | 适用 |
|---|---|---|---|---|
| **手写默认** | 文楷 | Caveat | JetBrains Mono | 设计稿就是这一套，默认值 |
| **阅读优先** | 文楷 | 文楷 | JetBrains Mono | 中英混排最一致，长文最舒服 |
| **系统原生** | 系统 | 系统 | 系统等宽 | 省内存、三端各自原生观感 |
| **极客等宽** | JetBrains Mono | Caveat | JetBrains Mono | 密度最高，中文长文会累 |

「手写默认」和「阅读优先」的差别只在 display：前者中文标题会从 Caveat 回退到文楷，导致中英混排时标题一半手写一半楷体；后者统一用文楷，牺牲一点个性换一致性。

**自动归位**：用户逐个改角色后，如果结果恰好等于某个预设，`presetId` 会自动切回该预设 —— 避免出现"配置和预设一模一样却标着自定义"的怪状态（`FontState.withRoleFont`）。

## 5. 加载与持久化

### 5.1 时序：必须在 `runApp` 之前

```dart
Future<void> main() async {
  WidgetsFlutterBinding.ensureInitialized();
  final fonts = await FontService.boot();     // 读配置 + 注册导入字体
  runApp(ProviderScope(
    overrides: [fontServiceProvider.overrideWithValue(fonts)],
    child: const VaultApp(),
  ));
}
```

用 override 注入而不是在 provider 里 `await`，是为了让**首帧**就用上正确字体。这是这一整套设计里唯一不能妥协的时序要求。

### 5.2 存储：JSON 而不是数据库

```
<appSupport>/fonts/
  index.json            预设 + 角色映射 + 导入字体清单（不含绝对路径）
  files/<sha256>.ttf    导入的字体文件，内容寻址
```

三个理由：

1. 字体是**纯本地配置**，不参与同步，不需要事务、不需要索引。
2. 必须在数据库打开之前就能读到（否则又回到"先系统字体再切"的问题）。
3. 一个 JSON 文件比"为了字体先初始化 drift + 密钥"简单一个数量级。

**绝对路径不入库**：iOS 应用沙盒路径在系统升级后会变，只存文件名，每次启动用当前 `files/` 目录重新拼（`FontFace.fromJson` 的 `resolvedDir` 参数）。这是 iOS 上最常见的一类"升级后数据丢失"事故。

写入用 `临时文件 → rename`，断电或崩溃不会留下半截 JSON。

### 5.3 状态如何流到界面

```
FontService (ChangeNotifier)
   ↓ Provider 注入
VaultApp (ConsumerWidget) → ListenableBuilder
   ↓ SketchTypography.resolve(state)
SketchTheme.build(typography:) → ThemeData
   ↓ ThemeExtension
context.type / context.typography
```

`SketchTypography` 是 `ThemeExtension`，业务代码一律写 `context.type.monoStyle(...)`，**禁止在 widget 里写死字体家族名** —— 和"禁止写死十六进制色值"是同一条纪律。

## 6. 字体不参与同步

`FontState` 明确不进 WebDAV。理由三条：

| 理由 | 说明 |
|---|---|
| **体积** | 一套中文字体 13 MB，同步一次的成本远超收益 |
| **许可** | 用户导入的字体授权千差万别，我们不代为分发 |
| **需求本身不成立** | "我这台 Windows 用等宽、手机用文楷"是完全合理且常见的偏好 |

代价是换设备要重选一次。**内置字体不需要重装**（在包里），只有导入字体需要重新导入 —— 这在文档和 UI 里都写明了（`_NotesCard` 第一条）。

> 未来可选项（P2）：把字体文件放进用户自己的 WebDAV（`/vault/fonts/`），像模型仓库那样"设备 A 下载、设备 B 复用"。技术上没有障碍，但需要用户主动开启，且要提示占配额。目前**不做**。

## 7. 导入：五个必须处理的现实问题

### 7.1 按字节校验，不看扩展名

用户从网上下的 `.ttf` 里，有相当比例其实是 woff2、压缩包、甚至是 404 页面改的扩展名。

```dart
// FontValidation.sniff —— 只看前 4 字节
00 01 00 00 / 'true'  → TrueType       ✅
'OTTO'                → OpenType       ✅
'ttcf'                → Collection     ✅
'wOFF'                → WOFF           ❌ 提示转 TTF
'wOF2'                → WOFF2          ❌ 提示转 TTF
其它                   → 不是字体        ❌
```

Flutter 引擎只认裸 sfnt，WOFF/WOFF2 是 Web 容器格式，必须先用 fonttools 解压。

### 7.2 不依赖文件路径

Android 从 SAF（系统文件选择器）拿到的 `content://` URI 没有本地路径。所以导入走的是 **"名字 + 读字节的闭包"**：

```dart
class FontImportSource {
  final String name;
  final Future<Uint8List> Function() read;
}
```

`core` 层因此完全不依赖 `file_picker`，页面层负责把 `PlatformFile` 转成 `FontImportSource`。

> 同时这也绕开了一个经典坑：`FileType.custom` + `allowedExtensions` 在 Android 上依赖 MIME 映射，`ttf` 常常没有注册 MIME，结果选择器直接变灰或返回空。这里统一用 `FileType.any`，靠字节校验兜底。

### 7.3 家族名由内容哈希生成

```dart
family: 'imp_${sha256(bytes).substring(0, 12)}'
```

原因：**`FontLoader` 只能加、不能卸**，同一家族名重复 `load()` 会抛异常。用哈希保证"同内容同名字、不同内容必不同名"，重复导入同一个文件也能直接跳过（`skipped`）。

### 7.4 体积上限 40 MB

中文字体最大也就 20~30 MB。超过 40 MB 基本都是把一个 ttc 打包了多个字重，整个加载进内存会 OOM。上限写死在 `FontValidation.maxBytes`。

### 7.5 导入字体没有真粗体

运行时注册的字体拿不到字重/字形元数据 —— 一个文件就是一个家族，粗体全靠合成。这条限制**无法绕过**（除非改 pubspec，那就不是"导入"了），所以直接写在设置页的说明里，不藏。

## 8. 设置页结构

```
设置 · 字体
├── 预设方案           4 张卡片，每张用自己的字体渲染 "拾遗 · Aa 14:02"
├── 分别指定
│   ├── 界面与正文     横向列表：文楷 / 系统 / 已导入…
│   ├── 标题与展示
│   └── 数字与等宽
├── 导入字体           选择文件 → 逐个校验 → 报告（成功/重复/失败逐条列出）
├── 已导入            名称（用该字体渲染）· 体积 · 原始文件名 · 重命名 / 删除
└── 关于字体           4 条说明：不同步 / 无真粗体 / 常驻内存 / 许可自负
```

几个细节：

- **预览必须用字体本身渲染**。文字写"霞鹜文楷"但用系统黑体显示，等于没预览。
- 选中态用便签黄 + 红描边 + 再歪一点，与全站规则一致（`SketchRadii.cycle` 轮换四套非对称圆角）。
- 删除正在使用的字体 → 该角色**退回系统字体**，不报错、不崩（`FontState.faceFor` 的兜底分支）。
- 启动时若有字体加载失败（文件被清掉/损坏），顶部显示一条红色提示，功能不受影响。

入口：所有页面的标题栏右上角齿轮（`PageScaffold` 通过 `AppActions` 注入，避免 `core/widgets` 反向依赖 `features`）。

## 10. 已知限制

| 限制 | 影响 | 现状 |
|---|---|---|
| 字体加载后不可卸载 | 切换过的导入字体会一直占内存 | 启动只加载当前用到的；说明里建议导入多了重启一次 |
| 运行时字体无真粗体 | 粗体是合成的，略糊 | 已写明；需要时给内置字体补 `weight` 声明 |
| 中文字体只有一套 | 用户想要宋体/黑体手写感只能自己导入 | 内置方案，后续可加"下载"通道复用模型下载器 |
| 首帧依赖 `main()` 里的 `await` | 启动多约 10~40ms（读 JSON + 注册字体） | 可接受；若以后变慢，先渲染骨架屏 |
| 字体不跨设备 | 换设备要重选 | 有意的设计（§6） |
| 无字体子集化 | 13.3 MB 全量进包 | 手写风需要生僻字兜底，子集化会掉字，暂不做 |
