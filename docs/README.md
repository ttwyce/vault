# Vault · 端侧优先的个人知识库

> 项目代号 **Vault**（产品名待定）· 三端：Android / iOS / Windows · 无自建后端 · WebDAV 同步 · 端侧 AI

**一句话定位**：把「笔记 / 想法 / 日记 / 网页归档 / 密码」统一进一个端到端加密的本地库，用自己的 WebDAV 同步，用端侧 AI 让三个月前看过的东西随时能被找回来 —— 数据永远在用户手里。

## 核心决策摘要

| # | 决策点 | 选择 | 代价 |
|---|---|---|---|
| D1 | 服务端 | 无后端，直连用户 WebDAV | 无推送、无服务端抓取、无协作 |
| D2 | 平台 | Android / iOS / Windows | 放弃 Web |
| D3 | 数据模型 | 统一 `entry` + `kind` 区分 | 视图层做差异化 |
| D4 | 同步粒度 | 一条 item 一个加密文件 | 文件数多，PROPFIND 成本上升 |
| D5 | 冲突策略 | 永不覆盖，冲突必留副本 | 需要冲突副本 UI |
| D6 | 变更检测 | 设备水位探测（1 请求） | 依赖每设备写状态文件 |
| D7 | 密码与 AI | 密码/日记走端侧模型（L0） | 端侧质量低于云端 |
| D8 | 向量同步 | 加密后随条目同步 | 需本地解密镜像表 + 模型一致 |
| D9 | 网页归档 | 正文层自动 + 快照层按策略 | 需配额与清理策略 |
| D10 | 模型分发 | 内置小模型 + 一键下载 | 需处理国内源与备份排除 |
| D11 | **首页定位** | **对话式（「聊天」），不是分类目录** | 需要会话抽屉做导航 |
| D12 | **视觉风格** | **手绘草图风（便签/硬阴影/虚线）** | 与"银行级安全"的企业感有张力 |
| D13 | **字体策略** | **三角色（正文/标题/等宽）+ 内置 3 套 + 用户导入** | 包体 +13.9 MB；字体不跨设备同步 |
| D14 | **本地库加密** | **SQLCipher 整库加密（`source: sqlcipher` 一行配置）** | 包体 +2~4 MB/ABI；需断言 `cipher_version` 防静默降级 |
| D15 | **密钥结构** | **主密码 → KEK → 包裹 DEK → HKDF 派生 5 条子密钥（无 oplog 子密钥）** | Argon2id 纯 Dart 实测 2.1s，解锁页必须有进度 |
| D16 | **恢复码** | **24 词 BIP-39（带校验和）+ HKDF，不跑 Argon2** | 抄错一个词当场可发现；恢复码 = 库的备份钥匙，必须警告不要截图 |
| D17 | **写入路径** | **`WriteGateway` 是唯一写入口，实体变更与 oplog 同事务** | 绕过它就等于静默丢同步；已在测试里用"故意失败"验证回滚 |
| D18 | **条目加密信封** | **明文头 {entity,id,rev} + AAD = 头部字节** | 解决"AAD 需要 rev 但 rev 在密文里"的鸡生蛋；oplog 与云端 item 字节一致，可直接 PUT |
| D19 | **活动埋点** | **按 (kind, entry) 时间窗口合并，不记流水账** | 浏览 30 分钟 / 编辑 5 分钟 / 搜索 60 秒；`dwellMs` 是最有价值的字段 |
| D20 | **路由判断** | **全 App 只有 `resolveGateScreen` 一处决定显示哪一屏** | 「未确认的恢复码」优先于状态机，否则 24 个词永远看不到 |
| D21 | **解锁进度** | **不伪造百分比，只显示真实秒数 + 不确定转圈** | Argon2id 没有进度回调；假进度条会在 1% 卡两秒，比没有更焦虑 |
| D22 | **meta.enc 写入** | **先写 .tmp 再 rename** | 它是解锁唯一入口，写一半断电等于永久锁死整个库 |
| D23 | **M3 开发顺序** | **纯判定层先于 WebDAV 接入** | 状态机 / 冲突 / 合并能确定性单测，真实 HTTP 行为留到集成层 |
| D24 | **并发触发** | **单飞锁忙时直接跳过，不排队** | 放弃排队触发，换取不会堆积几十次同步打爆请求预算 |
| D25 | **零丢失** | **编辑胜、冲突副本、密码永不字段合并** | 删除不能吞未同步编辑；冲突两边都留；密码只做 LWW + 旧值副本 |
| D26 | **部分分片扫描** | **`includeDeletes=false` 时不推断删除** | 没扫到的分片里文件"不见"不是删除，避免误删本地数据 |
| D27 | **M3 接入顺序** | **先无依赖内存编排，再确认真实 WebDAV 依赖** | 把条件写 / 412 / 墓碑顺序 / 预算先做成确定性测试；`pubspec.yaml` 未经确认不动 |
| D28 | **载荷边界** | **`SyncPayloadCodec` + `SyncWorkspace` 隔离加密与数据库** | 后续只替换 codec / backend / workspace，编排逻辑不重写 |
| D29 | **taxonomy 独立通道** | **category / tag / `entry_taxonomy` 只走 `/vault/entities/`，不跑 `merge3`** | 避免正文同步器把 taxonomy 信封当成 `EntrySnapshot`；同 rev 或更旧直接跳过 |
| D30 | **刚 PUT 的文件合入本轮 remote** | **PROPFIND 与 PUT 之间没有原子性** | 服务器尚未列出新文件时，diff 不能把它误判为远端删除 |
| D31 | **30 天清理闸门** | **本条墓碑 ETag 已确认 + 条目仍删除 + 无未推 oplog 才允许物理清空** | 只按到期时间删本地，另一台设备会把内容重新推回来；90 天墓碑 TTL 独立判定 |
| D32 | **统一调度保守闸门** | **正文 / taxonomy 任一链路不完整就跳过清理** | 本地物理删除与云端墓碑 DELETE 不可逆，不能在半轮同步状态下执行 |
| D33 | **90 天 TTL 只删云端墓碑** | **DELETE 必须带 `sync_state` 已确认 ETag 做 `If-Match`** | 本地已确认记录仍供 30 天清理闸门使用，两套依据互不删除 |
| D34 | **L2 删除列表也要落库** | **`diff.deleted` 在墓碑之后按规则 7 软删 / 编辑胜复活 / 清陈旧 ETag** | 墓碑缺失或过期时，远端 item 文件消失同样要同步；墓碑优先，不重复处理 |
| D35 | **物理清理不留孤儿行** | **30 天清空必须一并清掉 credential / vec / blob_ref / link_check / activity，diary_index 只置空命中列** | 派生表里指向不存在条目的行会在下次同步或重建索引时复活 |
| D36 | **增量游标与能力缓存落库** | **`sync/token` / `sync/capabilities` 走 `sync_state` 内部键** | 不新增表、不跑 codegen；省掉每轮全量 REPORT 与 OPTIONS |
| D37 | **MKCOL 只救目录** | **集合请求 / PUT 的 404/409 重建目录再重试，GET 文件 404 不建目录** | GET 404 是正常 diff 结果，盲目建目录会掩盖真实删除 |
| D38 | **退避错误码显式化** | **`SyncRunResult.retryCode` + `RetryScheduler` 可注入时钟** | 状态机只在 FAILED 保留 error；靠解析文案猜 E_NET/E_RATE 太脆 |
| D39 | **拖拽不改归属** | **分类只在同 parentId 内排序，跨级落点忽略** | 改层级是独立操作，不能靠一次拖拽悄悄完成 |
| D40 | **taxonomy 同 rev 用 HLC 判定** | **`resolveTaxonomyLww` 在 rev 并列时比较 HLC，无法判定则保留本地** | 只比 rev 会静默丢掉另一台设备同 rev 的更新（T22） |
| D41 | **一轮 = 一批 50 条** | **待推 oplog 默认上限 50，其余 `applied=0` 按 seq 续跑** | 不引入额外分批游标；500 会稳定撞满请求预算 |
| D42 | **远端同名标签自动合并** | **独立通道按 `usage_count` 大者保留，关联改指、另一方软删** | 直接插远端 id 会留下两个同名活标签，关联各挂一边（T21） |
| D43 | **删除分类本地/远端对称** | **两边都清条目关联 + 子分类提升为一级** | 只做一边会留下 parent_id 指向已删分类的孤儿（T23） |
| D44 | **真实 HTTP 后端只用 SDK** | **`dart:io HttpClient` 实现 WebDAV，无需新增依赖** | XML 按 response 块解析以兼容各家命名空间前缀；不接生产路径直到 M0 A5 确认 |
| D45 | **绝不把空 ETag 写进 syncState** | **PUT 无 ETag 时 HEAD 回读，仍无则抛 E_PATH** | 空 ETag 会让条件写悄悄降级成 createOnly，下轮 412 死循环 |
| D46 | **并发限流交给连接池** | **`HttpClient.maxConnectionsPerHost = 3`** | 只包 `_send` 的手写信号量管不到读响应体阶段 |
| D47 | **装配门面不自动启动** | **`VaultSyncRuntime.create()` 需要 WebDAV 地址与凭据，不接 App 启动** | M0 A5 未过前接线等于拿未验证的服务商行为跑生产同步 |
| D48 | **3xx 绝不自动跟随** | **关闭重定向并把 3xx 映射成 E_AUTH** | 会话过期重定向到登录页时，自动跟随会丢掉 If-Match 却返回 200 |
| D49 | **重试必须重新装配 workspace** | **`SyncCoordinator` 每轮重试重新 `load()`** | 复用旧对象会带着上一轮已落库的 sync_state / token 重复发请求 |
| D50 | **重启无需额外恢复逻辑** | **`applied=0` 的 oplog + 原子事务就是恢复点** | T15 落盘重开验证；任何额外「恢复表」都会引入第二个事实来源 |
| D51 | **超限载荷不进内存** | **默认 1 MB 上限，超限抛 E_QUOTA 而非静默截断** | 半个载荷会被当成损坏条目去解密；chunked 响应也要边读边挡 |
| D52 | **归档 L1 正文永不省** | **`decideArchivePolicy` 超配额只降快照层，不降正文层** | L1 是检索与 AI 的唯一输入源，省掉它「找回」功能直接废掉 |
| D53 | **403/451 不算死链** | **restricted 与 dead 分开判定，超时重试 2 次才 unreachable** | 把反爬误标成原站关停会误导用户删掉仍可访问的归档 |
| D54 | **归档写入口也走 WriteGateway** | **blob_ref / link_check / job_queue 的写入统一在事务内，重复检查只补非空字段** | 绕过唯一写入口或让重放抹掉 simhash 证据都会造成静默数据损坏 |
| D55 | **密码永不向量化** | **`planChunks(kind=6)` 直接返回空计划** | 密码进任何模型上下文都是不可接受的泄露面 |
| D56 | **向量模型配置写进 manifest** | **Gemma query/doc 前缀分离、Qwen3 last pooling 由 audit 校验** | 两个坑都不报错但召回率静默崩掉 |
| D57 | **密码明文零出设备** | **`CredentialGuard` 代码级脱敏 + prompt 扫描，健康报告只返回统计** | 靠 prompt 约束挡不住工具返回值夹带明文 |
| D58 | **空会话不落库** | **新对话是草稿态，首条消息才写 conversation** | 每点一次「新对话」就多一条空记录会填满抽屉（T26） |
| D59 | **工具策略统一闸门** | **所有 AgentTool 执行前过 checkToolCall，密码边界写成 deny** | 靠每个工具自觉或 prompt 约束挡不住明文泄露 |
| D60 | **AI 日记不向量化** | **kind=4 默认排除检索、不进语义空间、不可编辑** | 否则用户搜自己的东西会被大量生成文本占据 |

## 关键预算

| 指标 | 目标 |
|---|---|
| 冷启动到可交互 | < 1.2 s |
| 常规同步（无变化） | ≤ 3 个 HTTP 请求 |
| 常规同步（有变化） | ≤ 200 个请求 / 次 |
| 5000 条向量重建 | < 8 min（中端机） |
| 安装包体积 | < 60 MB |
| 峰值内存 | < 400 MB |
| 单条目体积 | 正文 ≤ 1 MB / blob ≤ 20 MB |
| **同步丢失容忍度** | **0** |

## 五条工程红线

1. **禁止无条件 PUT。** 所有写操作必须带 `If-Match` 或 `If-None-Match`。
2. **禁止全量同步 `blobs/`。** 快照按需下载。
3. **禁止混合不同 embedding 模型的向量。** 每条向量必须带 `model_id + dim`。
4. **禁止绕过 `VaultDatabaseOpener` 打开数据库，禁止只查 `cipher_version` 就认为已加密。**
   本项目全局用 SQLCipher，所以「忘了 `PRAGMA key`」的连接照样报出版本号，
   然后以明文建库。必须同时断言 `PRAGMA cipher_salt` 非空。
5. **禁止把密钥材料写进日志、异常信息或 `toString`。**
   `SecretBytes` 的指纹是 `sha256(key)` 的前 4 字节，不是密钥本身的字节。
   任何需要"认出这是哪把 key"的地方都用指纹，不要打印 `toHex()`。
